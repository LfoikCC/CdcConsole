# V11：用户、审计与目标表恢复

交付日期：2026-10-20。仅提供独立 Web，默认地址 http://localhost:8080。

## 使用入口

- 首次安装管理员：`admin / admin123`。已有账号不会在重启时重置。登录页不预填凭据，也不展示演示账号。
- 系统设置 → 用户管理：创建只读用户、普通用户和管理员，编辑、启停、软删除及重置密码。
- 顶部账户菜单：个人信息、修改密码、退出。
- 监控 → 审计日志：查看、筛选、展开脱敏配置及导出 CSV；只读用户不能导出。
- 任务详情 → 位点：共享采集位点、各目标投递位点、积压、历史趋势、只读源端诊断及恢复作业。
- 任务详情 → 表配置 → 重跑：明确选择目标订阅表，预检后提交恢复。

## 认证变化

REST 与 SSE 均要求本地会话。会话保存在 H2，有效期 8 小时。Cookie 为 HttpOnly、SameSite=Strict，HTTPS 使用 Secure。写请求需先获取 `/api/auth/csrf`，再发送 `X-CSRF-Token`。原无认证调用方需要调整登录流程。

普通用户可以运维已有任务；业务配置、邮件与用户管理仅管理员可修改。停用、删除、改角色、重置密码和修改自身密码均撤销相关会话及 SSE。最后一名启用管理员不能被删除、停用或降级。

## 恢复边界

恢复归属为单个目标订阅表，不回退共享源位点，不创建第二个 Debezium Worker。支持继续未成功批次、失败批次、本地采集时间回放和目标专属全量初始化。文件、校验和、连续性、generation 与映射兼容性通过真实预检确认；计划五分钟过期，提交重新校验。

快照完整落盘后再投递和顺序追平。恢复游标、文件引用、批次及错误持久化；完整快照可以复用，未完成扫描须明确重扫。主动回放采用新的作业批次 ID / StarRocks label，同一作业重试复用 ID，保留原事件 ID。恢复处理量独立统计。

全量默认不清空目标，源端已不存在的目标历史行不会自动删除。Kafka 必须额外确认重复消息风险。任务暂停或停止时，先恢复任务再提交重跑。

批次文件先落盘，主目标、公共捕获元数据、目标 fan-out 及删除审计在同一事务登记。登记事务失败时，启动恢复会从文件补齐各目标队列；新文件保存采集 generation，避免恢复已取消 generation 的孤立文件。
